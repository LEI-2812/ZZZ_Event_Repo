# 보상 화면과 XLSX 편집

## 화면

- 업적/기간 한정 보상: `Assets/Scenes/New/Reward List Scene.unity`
- 레벨 보상: `Assets/Scenes/New/Level Complete List Scene.unity`
- 데이터: `Assets/Resources/Data/game_data.xlsx`

두 씬의 Btn_Goback에는 RewardScreenActions.GoBack, Btn_Getreward에는 RewardScreenActions.GetSpecialReward가 On Click으로 연결되어 있습니다. 업적 및 레벨 구간 선택과 개별 보상 수령도 실제 Button 오브젝트의 On Click을 사용합니다.

기존 스테이지용 버튼·텍스트 오브젝트는 삭제하지 않고 목록용으로 재사용했습니다. 복사되어 있던 StageListActions 및 MainSceneActions 컴포넌트는 비활성화했습니다. 새 목록이 늘어나면 RewardGroupRow / RewardInfoRow 프리팹을 복제하며, 프리팹에서 배치와 디자인을 수정할 수 있습니다. 기존 버튼 스프라이트는 유지했고 새 수령 버튼에는 Sprite를 지정하지 않았습니다.

Main Scene의 보상·레벨 버튼, Event List Scene의 레벨 보상 버튼이 새 씬으로 연결됩니다. 기존 reward_list / rw_level은 사용 씬 등록을 해제했고 파일은 유지합니다. stage_list도 계속 비활성 상태이며 Stage List Scene을 사용합니다.

## 요청한 시트

| 시트 | 컬럼 | 의미 |
| --- | --- | --- |
| Achievement | id, name | 업적 이름. 8개 |
| Achievement_reward | id, items_id, info, level_id, amount | 개별 업적 보상. 24행 |
| level_reward | id, lv_num, items_id, amount | 레벨별 지급 아이템. 20레벨, 44행 |
| user | id, name, is_get_lm_reward, is_get_lv_reward | 현재 사용자 정보 및 특별 보상 획득 상태. id=1 사용 |

`Achievement_reward.level_id`는 `Achievement.id`를 참조합니다. 보상 한 행이 개별 수령 단위이며, 같은 업적의 보상들이 가운데 목록에 나타납니다. 왼쪽 분수는 해당 업적 보상의 수령 개수/전체 개수입니다.

`level_reward`는 같은 lv_num의 아이템을 묶어 한 번에 지급합니다. 화면에서는 레벨 1–10과 11–20 구간으로 나누고, 제목은 LV. 01 보상 형태로 표시합니다. item ID는 기존 game-data.json의 items를 참조합니다.

## 추가한 조건 시트

| 시트 | 컬럼 | 용도 |
| --- | --- | --- |
| achievement_condition | id, metric, target | id는 Achievement.id. 업적의 수령 조건 |
| special_reward | id, kind, items_id, amount | 특별 보상 지급 아이템 |

metric은 stage(클리어 스테이지 수), collection(보유 방부 수), evolution(진화 레벨 이상 방부 수)을 지원합니다. target은 필요한 수치입니다. 새 업적을 추가하면 같은 id의 조건 행도 추가하세요.

special_reward의 kind는 special(이벤트 특별 보상), maxlevel(레벨 완료 보상)입니다. 기존 특별 지급 아이템을 옮겼습니다.

## 수령 조건과 저장

- 일반 업적 보상: 업적 조건을 충족하고 이벤트 기간 안이어야 수령 가능
- 일반 레벨 보상: 해당 레벨 이상이어야 수령 가능
- 이벤트 특별 보상: 해당 이벤트의 모든 배틀을 완료하고 모든 업적 보상을 수령해야 획득 가능. 이벤트 기간 적용
- 레벨 완료 보상: 최고 레벨에 도달하고 등록된 모든 레벨 보상을 수령해야 획득 가능
- 수령 완료 보상은 재클릭하거나 씬을 다시 열어도 중복 지급되지 않음

user의 두 획득 여부는 0/1 또는 false/true입니다. XLSX에서 1이면 이미 받은 것으로 처리합니다. 플레이 중 새로 수령한 기록과 인벤토리는 기존 사용자 저장 파일에 보관합니다. **플레이 결과로 원본 XLSX를 덮어쓰지 않습니다.** 실제 표시 상태는 XLSX의 초기 획득 상태와 로컬 수령 기록을 함께 반영합니다. XLSX를 0으로 바꾸는 것만으로 기존 수령 기록이 초기화되지는 않습니다.

기존 저장 파일의 업적 일괄 수령 기록(a1 등)과 레벨 수령 기록(l1 등)을 유지합니다. 새 개별 업적 보상은 ar + 보상 id로 저장합니다. 이전 버전에서 이미 일괄 수령한 업적은 해당 아이템을 다시 지급하지 않습니다. 안정적인 기록 연결을 위해 기존 ID는 재사용하지 마세요.

## 데이터 수정

시트 이름과 첫 행의 컬럼 이름을 유지한 채 Excel에서 수정하고 저장하세요. Unity가 재임포트하면 Play 중 자동 반영됩니다. 편집 모드 미리보기는 Canvas의 Reward Screen Actions 메뉴에서 Reload Workbook / Update Scene Preview를 실행합니다. UI의 Workbook 참조는 같은 game_data.xlsx를 사용합니다.

기존 event_catalog와 stage_list 시트의 값은 변경하지 않았습니다. 아이콘 자산이 없는 보상은 기존 이미지 영역에 아이템 이름과 수량을 표시하며, Image의 Sprite는 직접 지정할 수 있습니다.

## 검증

Unity Play에서 목록 선택, 스크롤, 실제 Button 수령, 미달 조건 잠금, 중복 클릭 방지, 특별 보상과 레벨 완료 보상 수령, 저장 재로딩, Main/Event 왕복을 확인했습니다. XLSX의 이름·제목·수량·획득 플래그를 임시 변경해 실제 자동 반영도 확인한 뒤 복원했습니다. 수령 검증은 별도 QA 저장 파일에서 진행하여 사용자의 기존 진행 데이터는 유지했습니다. 실행 파일 빌드는 하지 않았습니다.

# 비스트-비트 스테이션 · Unity 구현

Unity 6000.6.0f1 / Windows / uGUI + Input System. 제작 기준: 제공된 제안서 38쪽, UI 문서 64쪽, 데이터 테이블 설명문서 23쪽.

## 실행

Unity 메뉴 **Beast Beat → 이벤트 씬 열기**를 선택한 뒤 Play.
씬: `Assets/Scenes/Event List Scene.unity`.
이벤트 이동 → 방부 도감 / 입양 → 방부 선택과 입양 → 챔피언 리그 → 배틀 시작.
첫 배틀에는 조작 안내가 표시됩니다. 마우스 클릭과 스크롤을 사용하며 Esc로 팝업을 닫거나 일시정지합니다.

씬 열기 메뉴는 기존 이벤트 씬을 열며, 씬을 생성하거나 빌드 목록을 변경하지 않습니다.
실제 젠레스 존 제로 계정이나 서버와 연결하지 않는 로컬 플레이 구현입니다. 보상도 로컬 인벤토리에만 지급됩니다.

## 문서에서 확정되지 않아 보완한 사양

아래는 원문 확정 사양이 아닙니다. `Resources/BeastBeat/game-data.json`에서 조정 가능합니다.

- 기본 피해량: Floor(((공격자 레벨+5)/10.0) × (공격력/대상 방어력) × SkillPower) + 2. SkillPower는 skills.dmg이며 일반 공격은 상성 1배, 속성 기술은 기존 1.3/0.7배를 적용한다. 기존 defenseFactor로 이중 차감하지 않는다.
- 속성 스킬 배율: 유리 1.3, 순환 불리 0.7, 기타 1.0. 전기/에테르는 서로 1.3.
- 기본 공격 배율 4.5, 속성 공격 5.4, 응급수리 최대 HP 30%. PP 15/8/5.
- 속성 공격의 화상·빙결·마비 부여 확률 25%. 화상은 최대 HP 6% 지속 피해, 빙결은 다음 행동 불가 후 해제, 마비는 25% 행동 불가. 지속 2턴.
- 모든 PP 소진 시 반동을 받는 발버둥 제공. 상대도 PP를 소모.
- 자발적 선수 교체는 상대의 공격 턴을 소모하고, 기절 후 강제 교체는 무료. 상대 방부를 쓰러뜨린 턴에 새 상대가 즉시 공격하지 않음.
- 동시 전멸은 패배. 패배와 도주는 보상 없음. 배틀 시작 시 전원 회복.
- 플레이어와 모든 보유 방부는 같은 레벨을 사용합니다. 스테이지 최초 클리어 시 `game_data.xlsx`의 `stage_list.level_gain`만큼 상승하며 최고 레벨은 20입니다. 재클리어·패배·연습 배틀은 레벨을 올리지 않습니다.
- `level_gain`은 0 이상의 정수입니다. 현재 14개 스테이지의 상승량 합계는 19이며 새 플레이어는 전체 최초 클리어 시 레벨 20이 됩니다. 0인 스테이지도 클리어 기록과 보상은 정상 지급됩니다. 이미 클리어한 스테이지의 값을 바꿔도 레벨은 소급 지급되지 않습니다.
- Battle 씬의 경험치 슬라이더와 `party.need_exp`, `party.current_exp`, `party.lv`는 사용하지 않습니다. 남아 있는 `party.level`과 예전 `users.bangboo_*_lv` 값도 아군 레벨을 결정하지 않습니다. 적 방부 레벨은 스테이지 설정을 따릅니다.
- 기존 저장 데이터의 플레이어 레벨·클리어 기록·아이템·보상 수령 기록은 유지합니다. 불러오기와 저장 시 모든 보유 방부의 레벨을 플레이어 레벨에 맞추고 이전 경험치는 0으로 정리합니다.
- 방부 LV10에서 코어 진화: 외형에 발광 장식 추가, 능력치 보너스. 진화 이름/진화 종족 데이터는 미제공이라 원래 이름 유지.
- 새 입양 방부는 플레이어 레벨로 합류. 첫 3속성은 LV1, 나머지는 LV2–8 해금.
- 스테이지 상세 NPC/대사/적 파티/레벨, 수량이 없는 보상과 업적 목표를 플레이 가능한 샘플 데이터로 보완.
- 워밍업·예선·본선·결승 목록과 순서는 `stage_list`의 종류와 아이디를 따릅니다. `s_name`은 스테이지 상세 제목에 단체 이름으로 표시됩니다.
- 특별 보상 조건은 UI p51의 구체적 조건인 ‘모든 업적 보상 수령’을 적용. 여기에는 결승 클리어와 도감 완성이 포함됨.
- 이벤트 종료일 미제공: 최초 로컬 실행 시점부터 14일 동안 한정 보상 활성. 기본 업적/레벨 보상은 만료되지 않음. 단말 시계를 사용하며 서버 검증 없음.
- 업데이트가 없는 독립형 버전이므로 NEW 알림은 별도로 생성하지 않음.
- 데이터 설명 PDF p3의 Google 스프레드시트는 접근 실패. 별도 원본 테이블 수치와 일치한다고 보장하지 않음.

## 데이터와 코드

- `BeastBeatData.cs`: 정수 코드, 정적 마스터 데이터, 유저 저장 모델.
- `ProgressService.cs`: 입양/편성/해금/성장/보상/저장. 정적 데이터와 유저 상태 분리.
- `BattleEngine.cs`: 프레임 및 화면과 독립적인 턴 처리. 테스트용 난수 시드 주입 가능.
- 현재 화면은 씬별 Actions 스크립트에서 제어합니다.
- `BattleSceneActions.cs`, `RewardScreenActions.cs`: 현재 전투·보상 화면 제어.
- `BangbooPortraits.cs`: 교체 가능한 임시 3D 방부 초상 생성.
- `Editor/BeastBeatSetup.cs`: 현재 이벤트 씬 열기, 규칙 검증, 전체 리그 시뮬레이션.

JSON은 원문의 관계를 따르는 테이블 배열입니다. 원문의 예시 `achievement_rewards.level_id`는 설명의 의미에 맞게 `owner_id`로 정리했습니다. `pause_list`의 중복 스테이지 정보는 실행 중 StageData 참조로 처리하고 `party`는 유저 저장 데이터로 분리했습니다. SQL 서버나 ORM은 사용하지 않습니다.

## 저장 및 아트

저장 위치: `Application.persistentDataPath/beast-beat-v1.json`.
임시 파일 작성 후 원자적 교체, 이전본 `.bak`, 손상본 별도 보존 및 백업 복구. 저장 실패는 화면 하단 안내. 신규 테스트는 별도 임시 경로를 사용합니다.

아케이드/경기장 배경은 사용자가 제공한 UI PDF에 포함된 이미지를 추출했습니다. 배경과 원문 캐릭터/IP의 권리는 해당 권리자에게 있습니다. 방부는 원본 모델이 아닌 색상·액세서리를 달리한 임시 3D 모델입니다. 원문에 등장하는 샤크부 등 UI 예시 대신 마스터 데이터 문서의 10종을 사용했습니다.
Windows의 맑은 고딕을 런타임에 사용하므로 다른 운영체제 배포 시 한국어 폰트 자산을 추가해야 합니다. 외부 패키지 다운로드와 원본 게임 설치는 필요하지 않습니다.

## 검증

Unity 메뉴 `Beast Beat → 검증 → 핵심 규칙 테스트` / `전체 리그 시뮬레이션`.
전체 리그 시뮬레이션에서 실패 시 진행 불가 스테이지를 출력하며, 자동 재도전 육성이 필요할 수 있습니다. 화면 및 실행 검증 결과는 배포 시 별도 기록합니다.

## 현재 엑셀 참조 규칙

- 시트 추가·삭제 없이 현재 game_data.xlsx를 사용합니다.
- event_list에 등록된 행은 모두 현재 이벤트이며 enabled 컬럼은 검사하거나 필터링하지 않습니다.
- users의 has_bangboo_1~has_bangboo_12는 같은 bangboo.id의 초기 보유 여부입니다. party.bid도 같은 ID를 사용하며 보유한 방부만 편성할 수 있습니다. 플레이 중 획득한 방부와 기존 저장 기록은 유지합니다.
- items의 id가 모든 보상 아이템의 기준입니다. 이벤트 reward_ids, 스테이지 reward_ids, achievement_reward/level_reward/special_reward의 items_id가 이 ID를 참조합니다. 존재하지 않는 ID와 중복 ID는 오류로 표시합니다.
- 아이템 이름과 등급은 JSON 대신 items에서 읽습니다. grade 1=금색, 2=보라색, 3=파란색, 4=회색입니다. 이름 미입력은 아이템 ID와 미입력 안내를, 등급 미입력은 회색을 표시합니다.
- stage_list의 reward_ids와 reward_amounts는 세미콜론으로 구분하며 같은 순서로 대응합니다. 예: 2;3;9와 2;3;1500은 아이템 2번 2개, 3번 3개, 9번 1500개입니다. 두 칸을 모두 비우면 아이템 보상이 없습니다. 기존 1~11번 지급량은 유지했고 새 12~14번은 같은 종류의 기존 스테이지 보상을 초기값으로 옮겼습니다.
- 엑셀에서 이름·등급·지급량을 수정하고 저장하면 각 화면의 재가져오기/실행 중 갱신에 반영됩니다. 사용자 진행 기록을 엑셀에 덮어쓰지 않습니다.
- 개발 검증 메뉴: Beast Beat → 검증 → 공통 레벨 성장 테스트 / 엑셀 시트 연결 테스트. 검증은 별도 임시 저장 파일과 미리보기 씬을 사용합니다.


## 씬 이동과 전투 데이터
- `Move_Scene.cs`가 8개 씬의 버튼 이동을 담당한다. 목적지는 이름/인덱스 대신 등록된 전체 경로를 사용한다.
- 이동 전 공통 데이터를 검증하며 실패 시 현재 씬에 오류를 표시한다. 전역 이동 잠금으로 연속 클릭에 의한 중복 로드를 막는다.
- 리그 버튼은 항상 스테이지 목록으로 이동한다. 파티는 배틀 시작 시 현재 엑셀/저장 편성으로 검증한다.
- `skills.dmg`는 스킬의 원본 위력(SkillPower), `dbf_type`/`debuff_type`은 NONE/PAR/FRZ/BRN/CNF, `dbf_prob`/`debuff_prob`는 0~100 정수 확률이다.
- 첫 기술은 일반 공격, 나머지는 속성 기술이다. 응급수리는 회복으로 유지하며 dmg만큼 HP를 회복한다.
- 혼란은 행동 시 33.3% 확률로 기술을 취소하고 고정 피해량 40의 물리 자해를 한다(상성 미적용). 취소 시 PP는 소비하지 않는다.
- `stage_party.stage_id`는 스테이지 ID, `b1_id/b1_lv`부터 `b3_id/b3_lv`까지는 적 1~3마리의 방부 ID/레벨이다. 뒤의 빈 슬롯은 생략할 수 있다.
- stage_party 행이 없는 스테이지는 기존 편성을 사용한다. 입력한 행이 잘못되면 임의 편성 대신 오류를 표시한다.
- 실제 시전한 스킬은 `[Battle]` Debug.Log에 라운드/진영/시전자/대상/이름/ID/효과/남은 PP가 기록된다.

## 보유 방부와 레벨 해금
- 보유 여부는 users.has_bangboo_ID=True 또는 플레이어 레벨 >= bangboo.release_lv로 판정한다.
- 과거 저장 파일의 owned 목록은 보유 판정의 근거가 아니다. 로드/엑셀 갱신 시 위 규칙으로 재구성한다.
- 레벨 해금 시 users.has_bangboo_ID 셀을 Excel Boolean TRUE로 변경하고 game_data.xlsx 원본에 저장한다. 다른 시트와 서식은 유지한다.
- 최초 클리어 레벨업 시 새로 해금된 방부 이름을 결과 메시지에 표시한다. 재클리어는 중복 해금하지 않는다.
- 보유 설정이 해제되고 해금 레벨에도 도달하지 않은 방부는 저장 편성에서 제외한다. party 시트 자체는 수정하지 않는다.
- 엑셀 저장 전에 진행도와 pendingWorkbookUnlocks를 먼저 저장한다. Excel 파일 잠금 시 진행도는 유지하며 3초 간격/재실행 후 재시도한다. 이미 True인 셀은 다시 쓰지 않는다.
- 에디터 원본 경로는 Assets/Resources/Data/game_data.xlsx이다. 임시 저장 파일을 쓰는 연습/테스트는 원본을 수정하지 않는다. 별도 실행 배포에서는 실제로 쓰기 가능한 XLSX 경로를 제공해야 한다.
## 레벨 능력치와 상태이상 (현재 규칙)
- HP = Floor(((Level - 1) / 19.0) * 1995) + 800; ATK/DEF = Floor(((Level - 1) / 19.0) * 160) + 50. 아군은 플레이어 레벨, 적은 stage_party의 개별 레벨을 사용한다.
- party.max_hp는 계산된 최대 HP를 덮어쓰지 않는다. 기존 hp/max_hp 비율을 새 최대 HP에 적용한다.
- 화상: 턴 종료에 최대 HP/16을 내림한 피해. 마비: 행동 시 15% 확률 취소, 전기 방부 면역. 빙결: 무작위 1~2회 행동 취소. 혼란: 행동 시 33.3% 취소 및 고정 40 물리 자해.
- 발생 확률은 skills.dbf_prob/debuff_prob의 0~100 정수이다. 빙결 외 상태는 기존 2턴 지속을 유지한다. 취소된 기술의 PP는 소모하지 않는다.
